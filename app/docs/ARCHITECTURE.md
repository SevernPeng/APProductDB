# 系统架构

## 边界

APProductDB 采用单体 Django 架构。业务按领域拆分，跨领域写操作集中在服务层，视图只负责鉴权、输入转换与响应。

| 模块 | 职责 |
| --- | --- |
| `accounts` | 公司账号、角色与权限 |
| `catalog` | 品牌、品类、产品、规格、数据表解析与初始化 |
| `comparison` | 对标关系、基准案例与横向比较 |
| `changes` | 变更申请、审核与冲突控制 |
| `imports` | Excel 校验、预览和事务性导入 |
| `audit` | 不可变审计记录 |
| `core` | 首页、产品查询、健康检查和共享能力 |

## 数据流

1. Excel 或数据表进入 `imports` / `catalog` 的校验流程。
2. 服务层在数据库事务内写入正式模型并记录来源。
3. 普通贡献者的人工修改进入 `changes` 审核队列。
4. 已发布数据由 `core` 和 `comparison` 只读展示。
5. 关键写操作进入 `audit`，运行时文件统一存放在源码目录之外。

## 设计约束

- 模型负责不变量和数据库约束，跨模型编排放在服务层。
- 所有导入先校验、再确认、后事务提交；失败时整体回滚。
- 上传文件、SQLite、日志和备份属于运行时状态，不进入 Git。
- `DJANGO_SECRET_KEY` 必须由环境提供；生产默认关闭调试模式。
- 外部数据表 URL 必须经过域名、协议、大小和私网地址校验。
- 新功能需同时增加权限测试、业务测试和失败路径测试。
